## 1. 目标

交付 **4 个功能完整、页面风格互不相同** 的独立前端演示系统，覆盖评分要求的全部能力点，便于在真实可运行环境中用脱敏样例数据录制演示视频（完整操作过程 + 处理结果）。

非目标：真实模型推理服务、真实 GPU 训练集群、跨项目共享 monorepo。

## 2. 约束与已确认决策

| 项 | 决策 |
|---|---|
| 交付形态 | 4 个完全独立前端项目（方案 A） |
| 技术栈 | Vue3 + Vite；每套不同 UI 库 |
| 数据 | 前端本地 mock + 脱敏样例资源 |
| 功能范围 | 每套均包含全部 4 大评分模块 |
| 风格差异 | 仅 UI 库、主题色、组件气质不同；信息架构一致 |

## 3. 项目划分

| 目录 | UI 库 | 视觉气质 | 开发端口 |
|---|---|---|---|
| `vla-demo-element` | Element Plus | 企业蓝灰、表格/流程密集 | 5101 |
| `vla-demo-antd` | Ant Design Vue | 中性专业、向导与对照布局 | 5102 |
| `vla-demo-naive` | Naive UI | 深色工作台、时间轴/帧标注 | 5103 |

各项目独立 `package.json` / `pnpm install` / `pnpm dev`，互不共享依赖包。

## 4. 功能范围（每套相同）

侧栏四大模块，对齐评分点：

### 4.1 多模态数据标注与质量控制（4 分）

1. **多模态能力（1.5）**：文本实体抽取、图像语义分割、语音切片、视频目标检测、点云分割。  
2. **任务协作闭环（1.5）**：标注任务创建、人员分配、状态流转、多人协作、批注管理、驳回返修、多级审核。  
3. **抽检回流（1）**：抽检规则配置、随机抽检、标注规范、合格通过、不合格驳回、合格数据回流。

### 4.2 自动化预标注（4 分）

1. **文本预标注（1.5）**：文本分类、实体识别、关系抽取、结构化结果输出、人工修正。  
2. **视觉预标注（1）**：OCR、YOLO 图像预标注、人工修正。  
3. **验收流程（1.5）**：预标注结果人工确认 → 标注 → 质量检查 → 结果验收。

### 4.3 VLA 智能数据采集与标注（8 分）

1. **采集配置（2.5）**：采集任务创建、场景信息、采集方案、采集模式、动作模板、人员配置。  
2. **联动标注与导出（3）**：视频/图像/文本说明/任务指令联动浏览；动作序列、关键动作节点、起止帧标注；导出 JSON、Excel、CSV。  
3. **样本质检（2.5）**：抖动、遮挡、模糊、数据缺失、样本与任务不匹配检测；不合格标记与过滤。

### 4.4 算法训练与验证（4 分）

1. **训练配置（2）**：算法配置、版本管理、模型与训练参数、训练任务创建、GPU 算力分配。  
2. **运行与指标（2）**：运行控制、数据增强、loss / accuracy / mAP 展示、训练结果与报表导出。

## 5. 信息架构与页面

### 5.1 通用骨架

- 顶栏：系统名、当前角色切换（标注员 / 审核员 / 管理员）、导出入口  
- 侧栏：四大模块 + 子菜单  
- 内容区：列表（筛选/状态）→ 详情/工作台

### 5.2 关键工作台

| 工作台 | 布局 | 关键交互 |
|---|---|---|
| 多模态标注 | 左资源 / 中画布或文本 / 右标签操作 | 切换模态类型；保存草稿；提交审核 |
| 流程协作 | 看板或步骤条 | 创建→分配→标注→审核→回流；批注；驳回返修 |
| 抽检 | 规则表 + 抽检结果 | 配置规则；随机抽检；通过/驳回；回流 |
| 预标注 | 原始 \| 模型结果 \| 人工修正 | 一键应用/修正/确认 |
| VLA 标注 | 上任务信息 / 中时间轴+关键帧 / 下动作与指令 | 打点起止帧；导出三格式 |
| 样本质检 | 检测结果列表 + 预览 | 标记不合格；过滤 |
| 训练 | 配置表单 → 任务卡 → 曲线 → 报表 | 启停；看 loss/acc/mAP；导出 |

### 5.3 建议录屏路径

按模块 1→2→3→4 顺序，每段展示：入口操作 → 可见处理过程（进度/状态跳转）→ 结果页或导出文件。

## 6. 数据与 mock 约定

- `src/mock/`：任务、人员、标注结果、抽检规则、训练任务与指标等 JSON  
- `public/samples/`：脱敏图片、短视频、音频波形图/短音频、点云预览图（可用静态图代替真实点云渲染若工期紧，但界面需标明「点云分割」并展示分割结果叠加）  
- `src/services/`：统一封装，写入 300–800ms 延迟，模拟处理过程  
- 导出：前端生成并下载 `.json` / `.xlsx` / `.csv`  
- 角色：本地切换即可，驱动不同按钮权限与待办列表

样例数据需看起来像真实业务（任务 ID、场景名、机器人动作名、时间戳），避免空白占位文案。

## 7. 工程约定

- 包管理：pnpm  
- 路由：vue-router，模块前缀清晰（`/qc`、`/prelabel`、`/vla`、`/train`）  
- 状态：pinia（轻量即可）  
- 图表：ECharts（训练曲线、抽检统计）  
- 每项目根目录 README：启动命令、端口、录屏检查清单（对照评分点）  
- 不引入真实后端；不强制 TypeScript（若脚手架默认 TS 可保留）

## 8. 风格差异落实方式

在信息架构相同的前提下，拉开差异的手段：

1. UI 组件库默认主题 + 定制主色  
2. 布局密度：Element 偏紧凑表格；Naive 偏深色大画布；Arco 偏卡片仪表盘；Ant 偏步骤向导  
3. 空状态、按钮层级、表格 vs 卡片列表的默认选择不同  

禁止做成「换皮」到无法辨认模块；菜单文案与演示路径保持一致，方便评委按同一脚本验收。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 四点云真实渲染成本高 | 首期用预览图 + 分割蒙版结果列表，界面完整走通 |
| 四套重复开发量大 | 先做一套「功能基准」（建议 Element），再复制并替换 UI 层 |
| mock 过程不够「真实」 | 统一进度条、日志抽屉、状态时间线 |
| 导出格式扣分 | 三格式各做一次真实下载并在 README 写明验证步骤 |

## 10. 实现顺序（供后续计划引用）

1. 搭 `vla-demo-element` 脚手架与四大模块空壳  
2. 填满 mock + 全部得分点页面与交互（功能基准）  
3. 复制为 antd / naive / arco，替换 UI 库与主题，回归同一录屏脚本  
4. 四套 README 与录屏检查清单  

## 11. 验收标准

- 四套均可 `pnpm install && pnpm dev` 独立打开

- VLA 模块能下载 JSON、Excel、CSV  
- 录屏可见操作过程与处理结果，使用脱敏样例数据  
- 四套视觉可明显区分（UI 库 + 主题）
