## 2. 分层职责

## 4. 关键设计决策

### 4.1 工作流引擎

- **选型**：自研轻量 DAG 执行器（节点注册表 + Celery chord/chain），前端用 AntV X6。  
- **原因**：招标节点类型固定、需与业务实体强绑定；全量引入 Airflow/Temporal 过重。  
- **执行模型**：`WorkflowDefinition`（版本化 JSON DAG）→ `WorkflowExecution` → `NodeExecution`。  
- **节点插件**：每个 nodeType 对应 Python handler，输入/输出为 JSON Schema。

### 4.2 同步 vs 异步

| 操作 | 模式 |
|------|------|
| CRUD、状态流转、保存标注 | 同步 REST |
| OCR/YOLO/NLP/抽帧/质检/训练/大导出 | 异步任务 + 轮询/WS |
| 训练指标、节点进度 | WebSocket 或 SSE |

### 4.3 演示 / 工程双模

```
VITE_DEMO_MODE=true  → services/* 走内存 mock（保证可录屏）
VITE_DEMO_MODE=false → services/* 走 /api/v1
```

禁止在工程模式下回退 `mockMetricPoint` 作为正式指标来源。

### 4.4 与其他三套演示的关系

| 产品 | UI | 本系统关系 |
|------|-----|------------|
| DataLink Element | 工单流 | 并行产品线，不共享运行时 |
| **AI Data Factory AntD** | 工厂流水线 | **本系统** |
| 灵眸 Naive | 创作台 | 并行 |
| 星算 Arco | 算力台 | 并行；训练 Worker 可复用设计 |

四套前端独立；后端/算法可按需抽公共包，但不强制 monorepo。

## 5. 部署拓扑（建议）

```
[Browser]
   │
[Nginx] ─ static ADF frontend
   │
[FastAPI x N] ─ [Redis] ─ [Celery Worker x N]
   │                │
[PostgreSQL]   [MinIO]
   │
[GPU Host] ─ OCR/YOLO/Train workers（可同机或独立）
```

最小可验证环境（单机）：Postgres + Redis + 1 API + 1 Worker + 本地文件存储。

---

## 6. 安全与审计

- JWT 访问令牌；刷新令牌可选。  
- 写操作二次校验角色（不仅前端隐藏按钮）。  
- 全量操作写入 `AuditLog`（对齐现有 `pushAudit` 字段）。  
- 对象存储使用预签名 URL，避免直传密钥到浏览器。

---

## 7. 可观测性

- API：请求日志 + traceId。  
- 任务：`WorkflowExecution` / `NodeExecution` 状态与耗时。  
- 训练：metrics.jsonl + 可选 TensorBoard 目录。  
- 驾驶舱：聚合查询（可物化视图或定时统计表）。

---

## 8. 演进路径

1. **M1**：前端新增 Factory 模块 + mock 可执行编排（演示工厂故事）。  
2. **M2**：FastAPI 持久化 + 队列，service 切 HTTP。  
3. **M3**：接入 OCR/YOLO/OpenCV 质检/最小训练 Worker。  
4. **M4**：GPU 监控、模型注册、评测中心、PDF 报表。

每阶段保持 20 分演示路径不断裂。
