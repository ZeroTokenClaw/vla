# 《自动化数据生产流程设计》

> 对应模块：AI 数据生产任务中心 + 流程执行监控  
> 目标：每个节点可配置、可运行、可重试、可审计，而非静态流程图。

---

## 1. 领域对象

| 对象 | 说明 |
|------|------|
| ProductionTask | 一次数据生产工单，绑定目标 Dataset 与 Workflow 版本 |
| Workflow | 流程模板（可多版本） |
| WorkflowNode | 节点定义：type、params、retry、timeout、条件边 |
| WorkflowExecution | 一次运行实例 |
| NodeExecution | 节点运行记录：状态、日志、输入输出快照、耗时 |
| ExportTask | 导出产物归档 |

状态：

```
ProductionTask: draft → ready → running → paused → succeeded | failed | cancelled
WorkflowExecution: pending → running → succeeded | failed | cancelled
NodeExecution: pending → queued → running → succeeded | failed | skipped | retrying
```

## 2. 标准流水线模板（出厂预置）

### 2.1 多模态标注生产线

```
数据导入 → 文件解析 → [按模态分支]
  ├─ 文本 → NLP实体识别 → 人工标注 → 质量检测 → 人工审核 → 数据导出
  ├─ 图像 → YOLO检测 → 图像语义分割(可选) → 人工标注 → 质检 → 审核 → 导出
  ├─ 语音 → 语音切片 → 人工标注 → 质检 → 审核 → 导出
  ├─ 视频 → 视频帧提取 → YOLO检测 → 人工标注 → 质检 → 审核 → 导出
  └─ 点云 → 点云分割 → 人工标注 → 质检 → 审核 → 导出
```

### 2.2 预标注加速线

```
数据导入 → 模型配置(OCR/YOLO/NLP) → 自动推理 → 人工确认修正
 → 质量检测 → 验收通过 → 数据回流 Dataset
```

### 2.3 VLA 具身数据线

```
采集任务绑定 → 多模态同步导入 → VLA数据结构化
 → VLA质量检测 → (不合格→异常处理/返工) → 合格回流
 → 数据导出(JSON/Excel/CSV) → 算法训练节点(可选)
```

### 2.4 训练闭环线

```
Dataset 选择 → 算法训练节点 → 指标收集 → 模型版本归档 → 导出报表
```

## 3. 十六类节点规格

| 节点类型 | nodeType | 执行器 | 关键输入 | 关键输出 |
|----------|----------|--------|----------|----------|
| 数据导入 | `import` | media-worker | uri/files | sampleIds[] |
| 文件解析 | `parse` | media-worker | sampleIds | meta(json) |
| 视频帧提取 | `frame_extract` | ffmpeg | videoSampleId, fps | frameSampleIds[] |
| OCR 识别 | `ocr` | ocr-service | imageIds, modelVersion | ocrResults[] |
| YOLO 检测 | `yolo` | det-service | imageIds, modelVersion, conf | boxes[] |
| NLP 实体识别 | `nlp_ner` | nlp-service | textIds, modelVersion | entities[] |
| 文本关系抽取 | `nlp_rel` | nlp-service | textIds, entities | relations[] |
| 图像语义分割 | `seg` | seg-service | imageIds | masks[] |
| 语音切片 | `audio_slice` | audio-worker | audioId, vadParams | slices[] |
| 点云分割 | `point_seg` | pc-worker | cloudId | segments[] |
| 人工标注 | `human_annotate` | human-gate | sampleIds, modality | annotationTaskId（等待完成） |
| 质量检测 | `quality_check` | quality-worker | sampleIds, rules | issues[], passIds |
| 人工审核 | `human_review` | human-gate | taskIds | reviewRecords |
| VLA 结构化 | `vla_struct` | vla-worker | vlaTaskId | modalityRelations, actions |
| 数据导出 | `export` | export-worker | sampleIds, formats | exportTaskId, files |
| 算法训练 | `train` | train-worker | datasetId, algoConfig | trainingTaskId, metricsRef |

### 3.1 人工门禁节点

`human_annotate` / `human_review` 进入 `waiting_human`：  
创建或关联 AnnotationTask / ReviewRecord，人工完成后通过回调/轮询驱动下一节点。

### 3.2 条件分支

边上配置表达式，例如：

```json
{ "when": "quality.passRate >= 0.95", "to": "export" }
{ "when": "quality.passRate < 0.95", "to": "human_annotate" }
```

### 3.3 失败重试

节点级：`maxRetries`、`backoffSec`、`retryOn: [TIMEOUT, MODEL_ERROR]`。  
任务级：支持整单 `retry`（从失败节点或从头）。

## 4. 可视化编辑器交互

页面：`/factory/workflow/:id?`

| 区域 | 功能 |
|------|------|
| 左侧节点库 | 16 类节点按「接入/算法/人工/质控/产出」分组 |
| 画布 | 拖拽、连线、多选、对齐、缩放 |
| 右侧属性 | 节点参数表单（模型版本、阈值、人员、路径） |
| 顶栏 | 保存草稿、发布版本、试运行、运行日志 |

版本策略：`draft` 可编辑；`published` 不可改，只读克隆为新 draft。

## 5. 运行时序列

```
用户点击「运行」
 → API 创建 WorkflowExecution(pending)
 → Celery 投递 run_execution
 → 按拓扑排序调度可运行节点
 → NodeExecution: queued→running
 → handler 执行，写 logs + output_ref
 → 成功则激活后继；失败则 retry 或标记 execution failed
 → human-gate 暂停 execution（status=waiting_human）
 → 人工完成后 resume
 → 全部汇聚成功 → ProductionTask.succeeded
 → WS 推送进度到监控页
```

---

## 6. 监控页指标

页面：`/factory/monitor`

- 卡片：总量 / 执行中 / 等待 / 已完成 / 失败  
- 列表：任务、模板版本、进度条、当前节点、耗时、操作（重试/取消/日志）  
- 详情抽屉：DAG 节点着色（绿成功/红失败/蓝运行/灰等待）+ 日志流

---

## 7. 与评分点的关系

编排本身不单独占分，但必须能串联并触发：

- 4 分标注/审核/抽检节点  
- 4 分预标节点  
- 8 分 VLA 结构化与质检节点  
- 4 分训练节点  

演示要求：至少跑通「预置 VLA 生产线」与「预标注加速线」各一条，节点日志与产物可核验。
