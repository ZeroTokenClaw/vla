# 《AI 模型及训练管理设计》

> 对应评分：7.1（2 分）+ 7.2（2 分）  
> 基线：`/train/config` `/train/runner` `/train/metrics`  
> 硬约束：**指标必须来自实际训练运行；禁止 mockMetricPoint 作为工程模式正式数据源。**

---

## 1. 页面结构

| 页面 | 路由 | 职责 |
|------|------|------|
| 算法配置中心 | `/train/config` | 算法/框架/入口/环境/配置文件 |
| 模型版本管理 | `/train/models` | 权重、预训练、版本对比【升级】 |
| 训练任务中心 | `/train/jobs` | 任务列表与创建（可与 config 合并入口） |
| GPU 资源调度 | `/train/gpus` | 设备列表、显存、利用率【升级】 |
| 训练监控中心 | `/train/runner/:id?` | 启停暂停恢复、日志 |
| 模型评测中心 | `/train/eval/:id?` | 验证集指标、混淆矩阵【升级】 |

---

## 2. 算法与版本

### 2.1 Algorithm

名称、类型（det/seg/nlp/vla）、框架（PyTorch）、描述、入口脚本、运行环境（conda/image）、配置文件模板。

### 2.2 AlgorithmVersion / ModelVersion

- 语义版本 + changelog  
- 权重 URI、预训练来源、关联算法版本  
- 版本对比：超参 diff + 指标 diff  

### 2.3 训练参数

Epoch、Batch Size、LR、Optimizer、输入尺寸、数据集版本、数据增强策略。

---

## 3. GPU 算力

| 字段 | 来源 |
|------|------|
| 设备 ID / 型号 / 显存 | NVML 或模拟 agent（演示机无 GPU 时明示） |
| 利用率 / 显存占用 | 实时拉取 |
| 任务分配 | TrainingTask.gpuIds 互斥锁 |
| 状态 | free / busy / error |

调度策略（最小）：手动选择空闲卡；冲突拒绝。后续可加队列优先级。

---

## 4. 训练任务生命周期

```
created → queued → running ⇄ paused → succeeded | failed | cancelled
                         ↘ retry → queued
```

操作：启动、暂停、恢复、终止、重试。  
权限：仅 Admin / 算法工程师。

---

## 5. 数据增强

翻转、旋转、随机裁剪、缩放、亮度、对比度、噪声——写入配置并在 Worker 实际应用（Albumentations / torchvision）。  
监控页展示已启用增强列表。

---

## 6. 指标与监控（真实性方案）

### 6.1 Worker 写出

```
runs/{trainingTaskId}/
  metrics.jsonl   # 每 epoch 一行
  train.log
  checkpoints/
  summary.json
```

`metrics.jsonl` 示例：

```json
{"epoch":1,"train_loss":1.02,"val_loss":1.10,"acc":0.42,"precision":0.40,"recall":0.38,"map":0.21,"lr":0.001,"elapsed_sec":82}
```

### 6.2 前端展示

- 实时：轮询或 WS 推送最新点  
- 曲线：Loss / Accuracy / mAP  
- 最佳模型：按 val_loss 或 mAP 选 checkpoint  
- 报表：参数 + 版本 + GPU + 指标 + 结论；导出 Excel / CSV / PDF  

### 6.3 无 GPU 环境的可验证降级

允许跑 **CPU 微训练**（极少 step 的 YOLO/分类 demoscript），仍产生真实 jsonl；  
**禁止**用随机数函数冒充。演示模式可保留 mock，但 UI 必须标记 `Demo Metrics`。

---

## 7. 与工厂流水线

节点 `train`：创建 TrainingTask → 等待 succeeded → 输出 `modelVersionId` + `metricsRef`。  
失败：节点 retry 或人工介入。

---

## 8. 验收要点

1. 创建训练任务并分配 GPU（或 CPU demo 设备）。  
2. 启动后日志滚动增加。  
3. 指标曲线随 epoch 变化且可回溯到 metrics.jsonl。  
4. 导出报表字段与任务配置一致。  
5. 暂停/恢复/终止状态机正确。
