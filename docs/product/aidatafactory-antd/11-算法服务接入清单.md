# 《算法服务接入清单》

> 所有算法服务独立进程/Worker，支持任务状态回传、失败重试、运行日志。

---

## 1. 服务总表

| 服务名 | 职责 | 推荐实现 | 资源 | 对应节点/页面 |
|--------|------|----------|------|---------------|
| `media-worker` | 导入、解析、FFmpeg 抽帧 | FFmpeg + Pillow | CPU | import/parse/frame_extract |
| `nlp-service` | 分类/NER/关系 | transformers 中文 NER 或 LLM JSON | CPU/GPU | nlp_ner/nlp_rel；文本预标 |
| `ocr-service` | OCR | PaddleOCR | CPU/GPU | ocr；OCR 中心 |
| `det-service` | 目标检测 | Ultralytics YOLOv8 | GPU | yolo；YOLO 中心 |
| `seg-service` | 语义分割 | 轻量分割模型或抓取 SAM 可选 | GPU | seg |
| `audio-worker` | VAD 切片 | silero-vad / webrtcvad | CPU | audio_slice |
| `pc-worker` | 点云分割预处理 | Open3D | CPU | point_seg |
| `vla-qc` | 抖动/模糊/遮挡等 | OpenCV | CPU | quality_check；VLA 质检 |
| `mismatch-service` | 语义不匹配 | 规则 + 可选句向量 | CPU | quality_check |
| `export-worker` | 大包导出归档 | Python xlsx/csv/json | CPU | export |
| `train-worker` | 训练与评测 | PyTorch 脚本 | GPU/CPU | train；训练中心 |
| `gpu-agent` | NVML 监控 | pynvml | 本机 | GPU 调度 |

## 2. 统一任务协议

请求：

```json
{
  "jobId": "JOB-...",
  "taskType": "ocr",
  "modelVersion": "paddleocr-v4",
  "params": {},
  "inputs": [{ "sampleId": "S-1", "uri": "s3://..." }],
  "callback": "http://api/internal/jobs/JOB-.../callback"
}
```

回调/状态：

```json
{
  "jobId": "JOB-...",
  "status": "succeeded|failed|running",
  "progress": 0.8,
  "outputs": [],
  "logs": ["..."],
  "error": null
}
```

重试：队列层按 `retry_policy`；业务错误（4xx 类）默认不重试。

---

## 3. 模型注册要求

| 字段 | 说明 |
|------|------|
| name / taskType | OCR/YOLO/NER/... |
| version | 语义化版本 |
| framework | paddle/pytorch/onnx |
| weightUri | 对象存储 |
| defaultParams | conf、imgsz 等 |
| status | active/deprecated |

预标页面必须可选 modelVersion 与参数。

---

## 4. 最小可验收部署（P0）

1. `ocr-service` + `det-service`：对 `public/samples` 出真实框/文字。  
2. `vla-qc`：Laplacian + 光流至少两项。  
3. `train-worker`：CPU 微训练写出 `metrics.jsonl`。  
4. 其余节点：先规则/ffmpeg 真执行，模型可后续替换。

---

## 5. 日志与追溯

- 每次推理保存：modelVersion、params、耗时、输入 sampleId、输出摘要。  
- 预标保存三套结果：model / human / final。  
- 训练保存 metrics 与 checkpoint 路径。
