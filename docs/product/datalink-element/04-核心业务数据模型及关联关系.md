# 《核心业务数据模型及关联关系》

> 目标：将现有前端内存对象升级为可持久化领域模型；字段尽量兼容当前 mock，降低改造成本。  
> 建议存储：PostgreSQL（元数据）+ 对象存储（媒体/模型文件）+ Redis（任务队列状态）。

---

## 1. 实体关系总览

```
Dataset 1──* Sample
Sample 1──* AnnotationResult
AnnotationTask *──* Sample（任务样本集）
AnnotationTask *──* Annotator（分配/协作）
AnnotationTask 1──* ReviewRecord
AnnotationTask 1──* AnnotationResult
QualityRule *──* Sample（抽检）
QualityRule → Dataset（回流目标）

Model 1──* PreAnnotationTask
PreAnnotationTask *──* Sample
PreAnnotationTask 1──* AnnotationResult（prelabel 类型）

VLATask 1──* Scene（或 scene 快照字段）
VLATask *──* ActionTemplate
VLATask 1──* ActionSequence（或 actions[]）
ActionSequence 1──* ActionNode
VLATask 1──* QualityInspection
VLATask *──* Device【升级】

Dataset 1──* TrainingTask
Model 1──* TrainingTask
TrainingTask *──* GPUResource
TrainingTask 1──* TrainingMetrics
TrainingTask 1──* Checkpoint
```

## 3. 关键关联约束

1. `AnnotationResult.sampleId` 必填；人工修正必须保留 `source=human_corrected` 并引用原 model 结果版本。  
2. 合格回流：`Sample.status=refluxed` 且写入 `Dataset` 版本增量。  
3. `PreAnnotationTask` 完成后生成 `AnnotationResult(source=model)`；验收通过可再生成 human 版。  
4. `TrainingTask.datasets[].versionPin` 必须指向已回流或已发布 Dataset 版本。  
5. `QualityInspection` 与帧/样本双向可追溯；过滤不删除原始 issue，仅标记。  
6. 所有写操作写 `AuditLog(actor, action, detail, at, entityType, entityId)`。
