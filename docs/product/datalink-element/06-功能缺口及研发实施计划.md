# 《功能缺口及研发实施计划》

> 范围：以 `vla-demo-element` 为产品壳与 API 形状基准，补齐提示词要求的真实业务能力。  
> 原则：不推翻四套演示壳；先做后端与算法，再替换 service 实现；无关模块不改。

---

## 1. 缺口分级

| 级别 | 定义 | 典型项 |
|------|------|--------|
| P0 | 影响「真实性」验收或演示被识破 | 训练指标 mock；无持久化；预标无真实推理可选项 |
| P1 | 影响评分点完整度 | 点云 3D、视频画框跟踪、设备管理、批量预标队列 |
| P2 | 体验与统计增强 | 人员质量看板、审核级数可配、GPU 实时曲线 |

## 3. 分期实施计划

### 第一阶段：现状冻结与契约（0.5–1 天）

- 冻结前端路由与 service 方法签名。  
- 增加 `VITE_API_BASE` / `DEMO_MODE` 开关。  
- 输出本目录 8 份文档作为基线（本阶段产物）。

**验收**：文档齐全；演示模式仍可 `pnpm dev` 录屏。

### 第二阶段：后端骨架与持久化（3–5 天）

- FastAPI/Nest 任选其一（建议 FastAPI，贴合算法 Python）。  
- 实现 QC / VLA / Prelabel / Train CRUD + 状态机后端校验。  
- 媒体上传 MinIO/本地目录。  
- 前端 `services/*` 增加 HTTP adapter，`DEMO_MODE` 回退 mock。

**验收**：刷新页面数据仍在；三角色登录后权限后端生效。

### 第三阶段：算法最小可用（5–8 天）

| 优先级 | 交付 |
|--------|------|
| 1 | OCR + YOLO 真实推理一路打通视觉预标 |
| 2 | 文本 NER 小模型或 LLM 结构化输出 |
| 3 | 训练 Worker：至少 YOLO 或现有仓库脚本跑通，metrics 入库 |
| 4 | VLA 质检：模糊+抖动 OpenCV；其余可规则+人工复核 |

**验收**：UI 展示 `modelVersion`；训练曲线与日志文件一致；关闭 `DEMO_MODE` 后无法用公式造点。

### 第四阶段：评分点补深度（3–5 天）

- 标注工作台：分割多边形、视频画框。  
- 预标批量任务队列与重试。  
- 设备台账、抽检统计、导出服务端大数据包。  
- 点云：若工期不够，保留深度预览并在说明书标注限制。

### 第五阶段：测试、演示脚本与加固（2–3 天）

- 按《07》用例回归。  
- 更新《08》脚本为「真实模式」路径。  
- 录制 15 分钟演示；异常态（驳回、权限、失败重试）出镜。

## 5. 风险与回滚

| 风险 | 缓解 |
|------|------|
| GPU/环境不具备 | 训练用小模型 CPU/单卡；现场带预跑完实验回放真实日志 |
| 点云引擎过重 | 不阻塞总分；文档声明 + 2D 预览保底 |
| 破坏四套演示 | 仅改 element 的 HTTP 适配；其它三套暂留 mock |
| 被要求证明非 mock | 打开原始 `metrics.jsonl` / 推理容器日志对照 |

回滚：`DEMO_MODE=true` 恢复纯前端演示，不影响已录视频路径。

---

## 6. 明确「不得虚构为已完成」清单

以下在文档发布日（2026-11-09）**不得**对外称为已具备真实能力：

1. 真实 GPU 集群调度与 NVML 监控  
2. 真实 OpenVLA/大模型训练完整流水线（除非 Worker 已接）  
3. 点云三维交互分割  
4. 基于视觉大模型的遮挡/任务匹配检测  
5. 跨浏览器持久化与多用户并发锁  

演示能力与工程能力必须在对外口径中分离。
