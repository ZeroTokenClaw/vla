# 《前后端接口及算法服务清单》

> 原则：前端继续调用 `src/services/*` 同名方法；演示阶段内存实现，工程阶段改为 HTTP。  
> Base URL 建议：`/api/v1`；鉴权：`Authorization: Bearer <token>`。

## 2. 算法 / Worker 服务清单

| 服务名 | 职责 | 推荐开源/方案 | GPU | 输入 | 输出 |
|--------|------|---------------|-----|------|------|
| `nlp-prelabel` | 分类/NER/关系 | transformers + 微调中文 NER；或 LLM JSON 模式 | 可选 | text, modelId, params | classify, entities, relations, structured, conf |
| `ocr-service` | OCR | PaddleOCR | CPU/GPU | image | boxes, text, conf |
| `det-service` | 目标检测 | Ultralytics YOLOv8 | GPU | image/video frame | xyxy, cls, conf |
| `vla-qc-vision` | 模糊/抖动/遮挡 | OpenCV Laplacian/光流；检测框 IoU 遮挡启发式 | CPU | video frames | issue[] |
| `vla-qc-semantic` | 任务不匹配 | 多模态相似度或规则（指令关键词 vs 动作标签） | 可选 | instruction + actions + frames | mismatch score |
| `train-worker` | 训练作业 | PyTorch / 现有 VLA-Training 脚本 | GPU | dataset version, hparams | logs, metrics.jsonl, ckpt |
| `gpu-agent` | 资源心跳 | NVML | — | — | util/mem/temp |

> 诚实约束：在算法服务未就绪前，API 可返回 `501` 或显式 `mode: "heuristic_seed"`，**禁止伪装成真实模型完成**。

## 3. 训练指标真实化契约

`train-worker` 每个 epoch 追加一行：

```json
{"epoch":3,"loss":1.02,"acc":0.71,"map":0.55,"lr":0.0001,"ts":"2026-11-09T12:00:01Z"}
```

后端解析入库 `TrainingMetrics`；前端只读。  
`mockMetricPoint` 仅允许 `DEMO_MODE=true` 时启用，默认关闭。

---

## 4. 异步任务与状态

| 任务类型 | 队列 | 状态 | 前端感知 |
|----------|------|------|----------|
| 预标批量推理 | Redis/RQ/Celery | pending→running→success/failed | 进度条 + 可重试 |
| VLA 质检 | 同上 | 同上 | QualityGate |
| 训练 | GPU 队列 | 同上 + stopped | Runner + SSE 日志 |

Webhook/SSE：`/api/v1/events/stream` 推送 `task.progress` / `train.metric`。

---

## 5. 审计与错误约定

- 所有写接口写 AuditLog。  
- 错误体：`{ code, message, details? }`  
- 业务拒绝（非法流转、无权限）→ `409` / `403`，与现前端 `throw new Error(message)` 文案兼容。

---

## 6. 导出

| 导出 | 现状 | 工程建议 |
|------|------|----------|
| VLA JSON/CSV/XLSX | 浏览器端生成（真实文件） | 可保留前端；大数据改服务端打包 |
| 训练报表 | 同上 | 优先服务端按 DB metrics 导出，避免伪造 |

---

## 7. 接口优先级（实施）

**P0**：QC 流转持久化、VLA 标注保存与导出、Train metrics 真实读写、鉴权。  
**P1**：OCR/YOLO/NLP 至少各一路可跑通推理。  
**P2**：VLA 视觉质检算法、设备台账、预标批量队列、GPU 实时监控。
